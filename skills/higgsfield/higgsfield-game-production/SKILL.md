# Higgsfield Game Production

Read [guide.md](references/guide.md). Specify the player, core loop, controls, win/loss, state, levels and feedback before art generation. Write a small GDD and test input/physics with placeholders; integrate art/audio once the mechanics are observable.

Asset beauty does not prove collision, weapon differentiation, destruction, tracking or performance. Define tests for actual controls, contact, recovery from invalid input and playable end states. A webcam interaction needs explicit permission at use time and handling of tracking loss.

Build, deploy, and marketplace publish are separate outcomes. Verify a playable result before calling it deployed, and keep publishing within the user's authorized scope. Do not infer current hosting, ownership, pricing or multiplayer behavior from the course demo.

Record failed media generations and human integration time as costs. Keep player count, concurrent users, remix and retention as separate metrics with time windows. Return GDD/assets/code or tested game as requested, plus observable tests and limitations. For game trailer imagery use cinematic direction instead. Apply the shared operating contract.
