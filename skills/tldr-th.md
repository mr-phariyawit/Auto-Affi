# TLDR (ไทย) — บอกตรง ๆ ว่าต้องทำอะไรต่อ

แปลผลลัพธ์ยาว ๆ / เทคนิค / ปนอังกฤษ → สรุปไทยสั้นที่ **เอา "ทำอะไรต่อ" ขึ้นก่อน**
แล้วจบด้วยคำสั่งที่มนุษย์กดได้เลย (เช่น "พิมพ์ go", "เลือก A") + บอก **สาเหตุ** + บอก **ผลที่จะเกิด**

## Output template (ใช้ตายตัวทุกครั้ง)
```
━━ TLDR (ไทย) ━━
🎯 ทำต่อ:    <สั่งให้ง่ายที่สุด: "พิมพ์ go" / "เลือก A" / "รัน <cmd>" / "วาง <file>" / "ไม่ต้องทำอะไร ✅">
📌 เพราะ:    <สาเหตุ 1 บรรทัด — ทำไมต้องทำ/ทำไมหยุดรอ>
➡️ จะได้:    <ผลลัพธ์ที่จะเกิดทันทีหลังทำ 1 บรรทัด>
⏱️ ด่วน:     <ทำเลย / รอได้ / กำลังบล็อก…>        ← ใส่เมื่อจำเป็น
👉 คำสั่ง:    <command/path ก๊อปวางได้เลย ถ้ามี>     ← ใส่เมื่อมี
```
ถ้าเป็น "ทางแยกต้องเลือก" → แตกตัวเลือกพร้อม **ผลของแต่ละทาง**:
```
🎯 ทำต่อ:    เลือก — พิมพ์ A หรือ B
   A) <ทำอะไร>  → จะได้ <ผลของ A>
   B) <ทำอะไร>  → จะได้ <ผลของ B>
📌 เพราะ:    <ทำไมต้องให้คุณเลือก (มัก = 1 ใน 4 หมวด: Identity/Irreversible/External/Approval)>
```

## Rules
1. **บรรทัดแรกต้องเป็น "กดอะไร" ที่ทำได้ทันที** — "พิมพ์ go" / "เลือก A" / "รัน …" / "วางไฟล์ …" ไม่ใช่คำอธิบาย
2. **ต้องครบ 3 เสมอ**: (ก) ทำอะไร (ข) เพราะอะไร (ค) แล้วจะเกิดอะไร — ขาดข้อใด = TLDR ไม่สมบูรณ์
3. **ไม่มีอะไรต้องทำ → "ไม่ต้องทำอะไร ✅ (FYI)"** ตรง ๆ
4. **มีตัวเลือก → บอกผลของแต่ละตัวเลือก** ไม่ใช่ลิสต์ A/B/C ลอย ๆ
5. **คง command / path / flag / ชื่อไฟล์ เป็นอังกฤษ** แปลแค่คำอธิบาย
6. **≤5 บรรทัด/เรื่อง**; หลายเรื่อง list เรียงตามด่วน
7. **ซื่อสัตย์**: blocked = บอก blocked; ยังไม่ verified = อย่าบอกเสร็จ
8. ในโปรเจกต์ AEGIS: เรื่องที่ไม่เข้า 4 หมวด MBP → มนุษย์ไม่ต้องตัดสินใจ (agent ทำเอง) → ใส่เป็น FYI

## When to use
- ปิดท้ายรายงานยาวของ agent / หลัง status / handoff
- มนุษย์พิมพ์: "สรุป", "ต้องทำอะไร", "ขอ TLDR", "อ่านไม่ไหว"
- ย่อ `.aegis/brain/human-queue.md` → "ตอนนี้ต้องทำอะไรบ้าง" เรียงตามด่วน

## Examples
เดินงานต่อ:
```
━━ TLDR (ไทย) ━━
🎯 ทำต่อ:    พิมพ์ go
📌 เพราะ:    plan พร้อมแล้ว รอแค่ไฟเขียวให้เริ่ม build
➡️ จะได้:    ผมรัน AFFI-S1-02 → S1-08 ต่อเองจนได้ master 1 ตัวที่ผ่าน gate
```
ทางแยก:
```
━━ TLDR (ไทย) ━━
🎯 ทำต่อ:    เลือก — พิมพ์ A หรือ B
   A) push ขึ้น origin เลย          → โค้ดขึ้น remote ทีมเห็น แต่ยังไม่ verified
   B) รัน test ผ่านก่อนค่อย push     → ช้ากว่า แต่ origin สะอาด
📌 เพราะ:    push = External access (1 ใน 4 หมวดที่ต้องให้คุณตัดสิน)
```
ไม่ต้องทำอะไร:
```
━━ TLDR (ไทย) ━━
🎯 ทำต่อ:    ไม่ต้องทำอะไร ✅ (FYI)
📌 เพราะ:    งานเสร็จ + verified + committed แล้ว
➡️ จะได้:    รอบหน้าลุยต่อได้เลย
```

(MBP: อย่าจบด้วยคำถามลอย ๆ — ออก TLDR ที่บรรทัด 🎯 สั่งได้เลย แล้วทำต่อตาม command-chain)
